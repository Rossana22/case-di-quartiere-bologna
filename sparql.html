Query SPARQL

Verifica di completezza e correttezza del grafo — tutte le keyword richieste, con risultati reali.

Keyword SPARQL utilizzate in queste query:

OPTIONAL DISTINCT UNION FILTER REGEX LIMIT ORDER BY BIND

Le query sono state eseguite su SPARQL Playground (motore Comunica, conforme a SPARQL 1.1) sul grafo unito (schema + 32 istanze), verificate in modo indipendente con rdflib. Dettagli sugli strumenti provati nella pagina Sfide.

Query 1 — Completezza strutturale delle 32 Case

Obiettivo: verificare che ogni Casa abbia gestore, indirizzo, orari e sito web, individuando eventuali lacune.

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX sm: <https://w3id.org/italia/onto/SM/>
PREFIX ac: <https://w3id.org/italia/onto/AccessCondition/>

SELECT DISTINCT ?nome ?haGestore ?haIndirizzo ?haOrari ?haSitoWeb
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome .
  OPTIONAL { ?casa bo:isManagedBy ?g . BIND(true AS ?haGestore) }
  OPTIONAL { ?casa clv:hasAddress ?a . BIND(true AS ?haIndirizzo) }
  OPTIONAL { ?casa ac:hasAccessCondition ?o . BIND(true AS ?haOrari) }
  OPTIONAL { ?casa sm:hasWebSite ?w . BIND(true AS ?haSitoWeb) }
}
ORDER BY ?nome

Risultato: 32 righe, una per Casa, senza duplicati. Indirizzo e sito web presenti su tutte e 32. Gestore assente solo per Stella e Tolmino. Orari assenti solo per Foscherara, Pilastro e Villa Mazzacorati.

Interpretazione: le lacune corrispondono esattamente alle celle vuote nel CSV originale per quelle stesse Case — il grafo riflette correttamente l'assenza del dato invece di inventarlo.

Query 2 — Coerenza testuale sui gestori (FILTER + REGEX)

Obiettivo: individuare i gestori che si dichiarano "APS" (associazione di promozione sociale).

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX cov: <https://w3id.org/italia/onto/COV/>

SELECT ?nome ?nomeGestore
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome ;
        bo:isManagedBy ?gestore .
  ?gestore cov:legalName ?nomeGestore .
  FILTER(REGEX(?nomeGestore, "APS", "i"))
}
ORDER BY ?nome

Risultato: 11 risultati, tutti effettivamente contenenti "APS" nel nome (es. "Graf San Donato APS", "Centro Sociale e Orti Villa Bernaroli APS").

Interpretazione: nessuna corrispondenza spuria — il testo importato dal CSV è pulito e coerente.

Query 3 — Case per quartiere (UNION)

Obiettivo: confrontare le Case di due quartieri (Navile e Savena) per verificare il collegamento al distretto.

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?nome ?quartiere
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome ;
        clv:hasAddress ?indirizzo .
  ?indirizzo clv:hasDistrict ?distretto .
  {
    ?distretto rdfs:label "Navile"@it .
    BIND("Navile"@it AS ?quartiere)
  }
  UNION
  {
    ?distretto rdfs:label "Savena"@it .
    BIND("Savena"@it AS ?quartiere)
  }
}
ORDER BY ?quartiere ?nome

Risultato: 13 righe — 7 Case a Navile (Casa Gialla, Croce Coperta, Katia Bertasi, Montanari, Villa Torchi, Fondo Comini, Pescarola) e 6 a Savena (Area Ortiva Paleotto, Casa del Gufo, La Dacia, Villa Mazzacorati, San Rafel, Foscherara).

Interpretazione: il collegamento clv:hasDistrict funziona correttamente per entrambi i quartieri testati.

Query 4 — Orari del lunedì (OPTIONAL)

Obiettivo: verificare che apertura/chiusura siano popolate coerentemente per una fascia specifica.

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX ac: <https://w3id.org/italia/onto/AccessCondition/>
PREFIX ti: <https://w3id.org/italia/onto/TI/>

SELECT ?nome ?apertura ?chiusura
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome ;
        ac:hasAccessCondition ?orario .
  ?orario ac:hasDayOfWeek ti:Monday .
  OPTIONAL { ?orario ac:opens ?apertura }
  OPTIONAL { ?orario ac:closes ?chiusura }
}
ORDER BY ?nome

Risultato: elenco coerente delle fasce del lunedì (es. Santa Viola 08:00-11:30 e 14:00-18:30). Un caso limite: Giorgio Costa risulta con apertura 13:00:00 e chiusura 00:00:00.

Interpretazione: il valore "00:00:00" come chiusura, formalmente valido, va verificato sul CSV sorgente — probabilmente indica un orario fino a mezzanotte da normalizzare (segnalato in Sfide).

Query 5 — Le 10 aperture più mattiniere (LIMIT + ORDER BY)

Obiettivo: controllo di plausibilità sui valori xsd:time di apertura.

PREFIX bo: <https://example.org/casediquartierebologna#>
PREFIX poi: <https://w3id.org/italia/onto/POI/>
PREFIX ac: <https://w3id.org/italia/onto/AccessCondition/>

SELECT DISTINCT ?nome ?apertura
WHERE {
  ?casa a bo:CasaDiQuartiere ;
        poi:POIofficialName ?nome ;
        ac:hasAccessCondition ?orario .
  ?orario ac:opens ?apertura .
}
ORDER BY ?apertura
LIMIT 10

Risultato: Katia Bertasi (07:00) la più mattiniera, seguita da un gruppo di Case alle 08:00, poi Montanari (08:45) e Casa del Gufo (09:00).

Interpretazione: tutti i valori sono plausibili per orari di apertura di un servizio comunitario diurno — nessuna anomalia tra i 10 più mattinieri.
